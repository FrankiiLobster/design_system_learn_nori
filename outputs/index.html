02 / TAXONOMY

分类不是目录，而是行为模型

一个组件属于什么大类，会向开发者和 Agent 暗示它的渲染方式、状态协议和无障碍责任。

维度分类传递的隐含信息
渲染机制Overlay 通常意味着 Portal、Backdrop、Z-index 和底层滚动锁定。
交互协议Forms 通常意味着 value、onChange、disabled，以及受控/非受控模式。
无障碍Disclosure 通常意味着 aria-expanded、焦点移动和键盘方向键行为。
语义 TokenFeedback 偏向 status-success / status-error；Forms 偏向 border-focus / bg-hover。

给 Nori 的分类原则

大类决定组件所处的上下文与默认行为。
小类决定组件承担的具体任务，例如 Sheet、Modal、Actionsheet。
Props把行为差异写成可组合、可验证的参数。
金句大类决定上下文，小组件决定 Props。
03 / COMPONENTS

Overlay 家族：先分容器，再分用途

对话里最有价值的一次辨析，是把视觉形态、业务用途和渲染架构拆成了三个层次。

命名关系从容易混淆的组件名，走向层级化模型
你的问题已形成判断

Bottom Sheet 是容器形态，Actionsheet 是业务用途

Bottom Sheet 是从底部滑出的通用模态容器，可以承载表单、筛选器、富文本或复杂 Card。Actionsheet 是它的一种预设用途：面向当前上下文提供一列操作按钮。

建议的 Nori 关系

  • Overlay / Sheet：基础容器
  • Sheet preset：Bottom、Center、Side
  • Actionsheet：面向操作列表的业务预设

为什么要这样拆

避免把两个底层实现重复维护，同时让 Agent 能从容器推断 Portal、遮罩、关闭行为，再从 preset 推断内容结构。

分类争议同一组件可以有不同分类视角
对比分析待 Nori 决策

为什么 gluestack 把 Actionsheet 放在 Disclosure？

这不一定是“谁对谁错”，而是两个分类系统在回答不同问题：Disclosure 关注用户意图与渐进揭示，Overlay 关注脱离文档流的渲染架构。

UX 视角

点击后向用户揭示更多操作或次要信息，因此可与 Accordion 放在同一语义家族。

Agent / 工程视角

需要 Portal、Z-index、Backdrop、ESC 或 Android 返回键时，归入 Overlay 更不容易产生歧义。

渲染约束浮层的“看起来在这里”不等于“渲染在这里”
技术约束可写入 Spec

Portal 是 Overlay 的结构性规则

组件在业务代码中可以嵌套在列表或页面内部，但打开时通常应传送到 UI 树顶层，避免 overflow 截断和局部 stacking context 导致的层级错误。

给 Agent 的明确约束

  • 挂载到全局 Portal / root layer。
  • 声明 Z-index 层级与 Backdrop 策略。
  • 声明是否锁定底层滚动，以及点击遮罩、ESC、返回键的关闭规则。
04 / PROTOCOL

状态和数据流，是设计规范的另一半

视觉稿里的一个“Disabled”或“Open”，在代码里对应的是数据拥有权、回调协议和交互边界。

Forms 组件Input、Checkbox、Select、Switch
状态协议高频模式

专业组件库通常同时支持两种模式，但业务常优先受控

受控模式让页面状态成为 Single Source of Truth，适合实时校验、组件联动、输入格式化和等待网络结果后再改变状态。非受控模式更适合简单表单或性能敏感场景。

受控

value + onChange。组件展示什么，由外部状态决定；组件只发出变化通知。

非受控

defaultValue。组件内部管理状态，外部在提交时读取结果，使用成本更低。

状态完整性从“有几个变体”转向“状态是否可执行”
诊断方法需落 Nori

状态不是装饰，而是组件的行为合同

Button、Input 或 Sheet 的状态应同时对应视觉表现、交互结果和数据约束。Agent 漏掉 Disabled、Error 或 Loading，不只是产出问题，也可能说明 States 规范不完整。

建议统一检查的状态面

  • 通用状态：default、hover、pressed、focused、disabled、loading。
  • 表单状态：invalid、required、readOnly、value / empty。
  • 边界条件：超长文本、空状态、异步失败、内容溢出、键盘与触控。
05 / HANDOFF

把组件写成 Agent 能执行的规范

对话已经给出一套清晰的最小结构：先讲组成，再讲接口，再讲状态和约束。

01

Anatomy

组件由哪些子件组成，例如 Sheet.Content、Overlay、DragHandle。

02

Slots

哪些位置可以被业务内容替换，哪些结构必须保留。

03

Props

把 snapPoints、isOpen、onClose、type 等核心 API 写成明确参数。

04

States & Constraints

说明状态、响应式规则、边界条件、Do / Don't 和可访问性。

// Nori / Sheet.spec.md 的结构草案
component: Sheet
category: Overlay
purpose: 通用浮层容器

anatomy:
  - Overlay
  - Content
  - DragHandle
  - Header
  - Body
  - Footer

props:
  type: bottom | center | side
  isOpen: boolean
  onClose: () => void
  dismissible: boolean
  hasOverlay: boolean

behavior:
  portal: required
  bodyScrollLock: when open
  escapeKey: close when dismissible
  androidBack: close when dismissible

states:
  closed / open / dragging / loading / error
a11y:
  focusManagement / aria-label / keyboardNavigation
